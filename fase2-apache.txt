PREGUNTA 2. ¿Que diferencia hay entre sites-available y sites-enabled?
-------------------------------------------------------------------------
  - sites-available/: guarda TODAS las definiciones (archivos .conf) de
    los Virtual Hosts que existen en el sistema, esten activos o no.
  - sites-enabled/: contiene enlaces simbolicos a los sitios que Apache
    carga realmente al iniciar. Solo lo que esta aqui se sirve.
  Se administran con a2ensite (activar) y a2dissite (desactivar), que
  crean/borran el enlace simbolico entre ambos directorios. Esto permite
  mantener varios sitios configurados sin tenerlos todos en produccion.

-------------------------------------------------------------------------
PREGUNTA 3. Ejecuten sudo apache2ctl configtest. ¿Que reporta?
           ¿Por que es importante antes de reiniciar?
-------------------------------------------------------------------------
Reporta "Syntax OK" cuando la configuracion es valida (o el error exacto
con archivo y linea cuando no lo es). Es importante porque valida la
sintaxis ANTES de aplicar los cambios: si se reiniciara con un error de
sintaxis, Apache no arrancaria y el sitio quedaria caido. configtest es
el "chequeo previo" que evita dejar el servidor fuera de linea.

-------------------------------------------------------------------------
PREGUNTA 4 (Reto). Si Apache no arrancara, ¿que 3 pasos seguiri
           para diagnosticar el problema?
-------------------------------------------------------------------------
  Paso 1: Ver el estado y los logs del servicio:
            sudo systemctl status apache2
            sudo journalctl -u apache2 -n 50 --no-pager
          El mensaje suele indicar la causa exacta (config invalida,
          puerto ocupado, permisos).
  Paso 2: Validar la configuracion:
            sudo apache2ctl configtest
          Corrige cualquier error de sintaxis o Virtual Host.
  Paso 3: Revisar puertos y conflictos:
            sudo ss -tlnp | grep -E ':80|:443'
            sudo lsof -i :80
          Verifica que el puerto 80 no este usado por otro servicio
          (por ejemplo IIS en Windows o Nginx) y revisa los logs en
          /var/log/apache2/error.log.
